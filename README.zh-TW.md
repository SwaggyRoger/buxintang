# 卜心堂

> 六爻金錢卦・解籤問心

一個 R Shiny 的卜卦 App。使用者親手擲滿六次銅錢成卦，程式依《易經》算出卦象，
再交給 Claude 扮演的「解籤師」斷卦。

**線上版：** https://rogerchen.shinyapps.io/buxintang/ · **English:** [README.md](README.md)

---

## 這個 App 到底做了什麼

多數「易經 App」是把六個數字丟給 LLM，指望它自己推出卦來。那一步是機械運算，
模型偏偏不擅長。這裡改成：**推卦由 R 算，模型只負責解**。

### 起卦 — 三枚銅錢（金錢卦）

三枚銅錢擲六次，由初爻至上爻。字（陽面）計 3，背（陰面）計 2：

| 合數 | 爻 | | 動爻 | 機率 |
|---|---|---|---|---|
| 6 | 老陰 | `▬▬ ▬▬ ✕` | 是 → 變陽 | 1/8 |
| 7 | 少陽 | `▬▬▬▬▬` | 否 | 3/8 |
| 8 | 少陰 | `▬▬ ▬▬` | 否 | 3/8 |
| 9 | 老陽 | `▬▬▬▬▬ ○` | 是 → 變陰 | 1/8 |

六擲必須擲滿。卦既起，中途沒有離座的按鈕。

### 斷卦

由六爻算出：

- **本卦** — 六十四卦之一，含卦名與卦辭
- **之卦** — 動爻盡變之後的卦
- **互卦** — 二三四爻為下互、三四五爻為上互，看事情的中段與檯面下的內情
- **爻題** — 初九、六二、九三⋯
- **該用哪段經文** — 依朱熹《易學啟蒙》變占法：

  | 動爻數 | 依據 |
  |---|---|
  | 0 | 本卦卦辭 |
  | 1 | 該變爻之爻辭 |
  | 2 | 兩變爻之爻辭，以上爻為主 |
  | 3 | 本卦與之卦兩卦辭，本卦為貞（主）、之卦為悔（次） |
  | 4 | 之卦兩不變爻之爻辭，以下爻為主 |
  | 5 | 之卦唯一不變爻之爻辭 |
  | 6 | 乾用「用九」、坤用「用六」，其餘用之卦卦辭 |

### 卜不過三

《易・蒙》卦辭：「初筮告，再三瀆，瀆則不告。」

同一件事第二次起卦會出現提醒，第三次籤師不開口。問句在比對前會正規化
（空白、全半形標點），而且**要卦成才算一次**——中途離開不記帳。

## 解籤師

算好的卦象會整理成一張**卦單**（卦名、卦辭、動爻爻題、之卦、互卦、斷卦法），
送給 `claude-opus-5`。模型完全不需要自己推卦。

人格定位是**一位深諳人情世故的解籤師**：在一間香火不算旺的小廟裡坐了三十年，
知道跪在面前的人問的是卦，求的其實是一句話——一句能讓他撐下去、或是讓他死心的話。

籤解六百到九百字，固定四段：

| 段 | 內容 |
|---|---|
| 【籤解】 | 這一卦是什麼光景、動爻動在哪、對他這件事意味著什麼 |
| 【打個比方】 | 一個貼著他實際處境的具體場景，不是寓言 |
| 【所以呢】 | 具體到可以照做的建議，並給一個可觀察的訊號 |
| 【啟】 | 一句帶得走的話 |

提示詞裡有一份**反公式化清單**。沒有它的時候，實測五篇籤解有 5/5 用「你大概⋯」
開場舉例、5/5 用「上卦X是⋯，下卦Y是⋯」開場斷卦——多求幾次就像在讀同一篇。
清單把這些開場指名禁止，並要求每一卦換一個切入點：卦名的字義、動爻的位置、
卦辭裡的某一個字，或先從他的處境講起再回頭對到卦。

[`R/03_interpreter.R`](R/03_interpreter.R) 最上面的 `CLAUDE_EFFORT` 預設
`"medium"`（一次解籤約 35–55 秒）。改 `"high"` 多花約三成時間，實測差異不大；
`"low"` 更快但明顯變淺。

沒有金鑰時 App 照常運作，改給一份依卦辭生成的**離線籤解**——卦象是真的，
只是沒有人味。

## 跑起來

```bash
Rscript -e "shiny::runApp('.', port = 7788, launch.browser = TRUE)"
```

相依套件只有三個：`shiny`、`bslib`、`httr2`。

### 設定金鑰

複製 `.Renviron.example` 為 `.Renviron`，填入金鑰，重啟 R session：

```
ANTHROPIC_API_KEY=sk-ant-...
```

`.Renviron` 已被 `.gitignore` 擋住，不會進這個 repo。程式碼裡沒有任何硬寫的金鑰。

### 測試

```bash
Rscript tests/test-divination.R
Rscript tests/test-claude-payload.R
```

兩支都不會呼叫 API。

## 部署到 shinyapps.io

```bash
Rscript deploy.R
```

第一次要先跑一次 `rsconnect::setAccountInfo(...)`，說明在 [`deploy.R`](deploy.R) 的註解裡。

**金鑰怎麼上去。** shinyapps.io **不支援** `rsconnect` 的 `envVars`——那是
Posit Connect 的功能，在這裡會直接報錯 `shinyapps.io does not support setting envVars`。
可行的做法是把 `.Renviron` 一起打包，伺服器端 R 啟動時會自動讀取。

> 代價要知道：金鑰因此存在部署包裡。它不對外公開（bundle 不提供下載，
> 對外只跑 Shiny app），但任何能登入這個 shinyapps.io 帳號的人都拿得到。
> 個人專案可以接受；要更嚴謹得換 Posit Connect。
>
> `.Renviron` 仍然不會進 git，只進部署包。

這個版本沒有第二個服務行程。舊版另外開一個 plumber API 在 `localhost:8000`，
那在 shinyapps.io 上跑不起來——那邊只跑 Shiny 這一個 process。現在 API 呼叫
直接寫在 Shiny server 裡。

落款時間固定用 `Asia/Taipei`（[`R/02_casting.R`](R/02_casting.R) 的
`DIVINATION_TZ`）。shinyapps.io 的機器跑 UTC，不指定的話台灣的上午會被記成丑時。

## 設計筆記

視覺定調「夜廟燭火」：暗、暖、安靜。金是香火，硃砂只留給動爻和印。
宣紙全場只出現一次——就是籤解那張，從一片墨黑裡翻出來。功能性的東西盡量退到後面，
讓節奏、留白和等待本身變成內容。

字體 Noto Serif TC。動畫全部尊重 `prefers-reduced-motion`；而且入場動畫一律是
「裝飾」而非「必要」——元素的預設樣式就是可見的，所以動畫時間軸沒在跑
（分頁在背景、瀏覽器節流）也不會讓卦象消失。
